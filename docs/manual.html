第1章 システム概要

1.1 本システムについて

本システムは、AIを活用した面接自動化プラットフォームです。構造化された質問をTTS（音声合成）で候補者に読み上げ、候補者はテキスト・音声・動画で回答します。回答はOpenAI GPT-4oまたはClaude等のLLMにより自動採点され、合否判定・強み弱み分析・採用推奨レポートが生成されます。

主な機能

機能説明
構造化面接事前定義された質問セット（シナリオ）に基づく体系的な面接
マルチモーダル回答テキスト・音声（Whisper STT）・動画からの回答受付
AI自動評価関連性・正確性・明瞭性の3軸でスコアリング（各0-100点）
自動合否判定設定した基準に基づく即時リジェクト・合否判定
セッション管理タイムアウト・中断再開・進捗追跡
結果レポートLLMによる面接サマリー、強み・弱み、採用推奨の自動生成
質問分岐前の回答に基づく動的な質問出し分け

3.4 評価スコア設定

回答評価は3つの観点で0-100点のスコアが付けられ、加重平均で最終スコアが算出されます。

評価軸重み説明
Relevance（関連性）40%質問に対して適切に答えているか
Correctness（正確性）40%回答内容が正確か
Clarity（明瞭性）20%回答が明確で分かりやすいか
最終スコア = (関連性 x 0.4) + (正確性 x 0.4) + (明瞭性 x 0.2)

デフォルトの合格基準: 70点（シナリオごとに変更可能）

3.5 メディア処理設定

設定項目デフォルト説明
最大動画サイズ500MBアップロード上限
最大音声サイズ25MBアップロード上限
最短音声時間0.5秒無音排除
最長音声時間600秒（10分）回答時間上限
ffmpegタイムアウト120秒動画→音声変換の上限

第4章 面接シナリオの作成

4.1 シナリオ（Situation）の作成

シナリオは面接テンプレートです。クライアント単位で管理され、複数の質問を含みます。

管理画面からの作成

クライアントでログイン後、/situations/new にアクセスしてシナリオを作成します。

Railsコンソールからの作成

bundle exec rails console

client = Client.find_by(email: 'client@interview.com')
situation = Situation.create!(
  title: 'エンジニア面接 - バックエンド',
  description: 'バックエンドエンジニアの技術面接',
  client: client,
  language: 'ja',
  session_timeout_minutes: 45,
  passing_score: 70,
  auto_reject_enabled: true,
  allow_resume: true,
  max_resume_count: 2
)

シナリオの設定項目

項目型デフォルト説明
title文字列-シナリオ名（必須）
descriptionテキスト-シナリオの説明
language文字列enen（英語）/ ja（日本語）
session_timeout_minutes整数60セッション制限時間（分）
passing_score整数70合格基準スコア（0-100）
auto_reject_enabled真偽true自動リジェクト機能の有効化
reject_on_required_fail真偽true必須質問の不合格で即リジェクト
min_required_score整数70必須質問の最低合格スコア
max_consecutive_fails整数0連続不合格の上限（0=無制限）
allow_resume真偽true中断後の再開を許可
max_resume_count整数3最大再開回数
archived真偽false非表示フラグ

4.2 質問（Question）の登録

situation = Situation.find(1)

# 自由記述の質問
situation.questions.create!(
  question_text: 'これまでのプロジェクトで最も挑戦的だった経験を教えてください。',
  question_type: 'long_answer',
  order: 1,
  required: true,
  category: 'experience'
)

# 選択式の質問
situation.questions.create!(
  question_text: '最も得意なプログラミング言語はどれですか？',
  question_type: 'choice',
  order: 2,
  required: false,
  options: {
    choices: ['Ruby', 'Python', 'JavaScript', 'Go', 'Other'],
    correct_answer: nil  # 正解なし（自由選択）
  }
)

# 複数選択の質問（正解あり）
situation.questions.create!(
  question_text: 'RESTful APIの特徴として正しいものを全て選んでください。',
  question_type: 'mcq',
  order: 3,
  required: true,
  options: {
    choices: [
      'ステートレスである',
      'セッション管理が必須',
      'HTTPメソッドを活用する',
      'SOAPプロトコルを使用する'
    ],
    correct_answers: ['ステートレスである', 'HTTPメソッドを活用する']
  }
)

4.3 質問タイプと設定

タイプコード説明評価方法
自由記述long_answerテキストまたは音声で自由回答LLMによるスコアリング
単一選択choice選択肢から1つ選択LLMまたは正解マッチ
複数選択multiple_choice選択肢から複数選択LLMまたは正解マッチ
正解付き選択mcq正解が定義された選択問題自動採点（100点 or 0点）

4.4 分岐ルール

質問に branching_rules を設定することで、前の回答結果に応じて出題を制御できます。

question.update!(
  branching_rules: {
    'conditions' => [
      {
        'question_id' => 1,           # 質問1の結果を参照
        'type' => 'score_above',      # スコアが基準以上なら
        'value' => 80,                # 80点以上
        'action' => 'include'         # この質問を出題
      }
    ],
    'default_action' => 'exclude'     # 条件不一致なら出題しない
  }
)

分岐条件タイプ

タイプ説明value
selected_option前の回答が特定の選択肢か選択肢テキスト
score_above前の回答スコアが基準以上かスコア閾値
score_below前の回答スコアが基準以下かスコア閾値
answered前の質問に回答したかtrue/false

4.5 自動リジェクト設定

シナリオに以下を設定することで、面接中のリアルタイムリジェクトが可能です。

リジェクト条件設定動作
必須質問失敗reject_on_required_fail: true
min_required_score: 70		required: true の質問で70点未満なら即座にfailed
連続不合格max_consecutive_fails: 33問連続で不合格基準未満ならfailed
平均スコア不足passing_score: 70面接完了時に全回答の平均が70点未満ならfailed

第5章 面接の実施フロー

5.1 面接開始

POST /api/interviews/start

リクエスト

{
  "situation_id": 1,
  "language": "ja"    // 省略時はシナリオの言語設定を使用
}

レスポンス（成功時 201）

{
  "success": true,
  "interview_id": 1,
  "access_token": "abc123...",
  "status": "in_progress",
  "total_questions": 5,
  "language": "ja",
  "session_timeout_minutes": 60,
  "remaining_seconds": 3600
}
access_token は以降のAPI呼び出しで X-Interview-Token ヘッダーに設定するか、パラメータとして送信できます。トークン認証を使えば、ユーザーログインなしで面接が実施できます。

ステータス遷移

  not_started ──> in_progress ──> completed (合格)
                       |
                       +──> failed (不合格/自動リジェクト)
                       |
                       +──> abandoned (タイムアウト/中断)
                                |
                                +──> in_progress (再開)

5.2 質問の取得と表示

GET /api/interviews/:id/next_question

レスポンス

{
  "success": true,
  "question": {
    "question_id": 10,
    "question_text": "これまでの経験を教えてください",
    "question_type": "long_answer",
    "audio_url": "/rails/active_storage/blobs/.../question.mp3",
    "order": 1,
    "required": true,
    "total_questions": 5,
    "options": null
  },
  "remaining_seconds": 3540
}

audio_url には質問文のTTS音声（MP3）のURLが含まれます。フロントエンドでこのURLを再生することで、候補者に質問を読み上げます。

全ての質問に回答済みの場合は "interview_complete": true が返されます。

5.3 回答の送信

POST /api/interviews/:id/submit_answer

回答方法は3種類

方法A: テキスト回答

Content-Type: application/json

{
  "question_id": 10,
  "text_answer": "私はRuby on Railsを5年間使用してきました..."
}

方法B: 音声回答

Content-Type: multipart/form-data

question_id: 10
audio_file: (音声ファイル .mp3/.wav/.webm)

方法C: 動画回答

Content-Type: multipart/form-data

question_id: 10
video_file: (動画ファイル .mp4/.webm)

レスポンス（成功時 201）

{
  "success": true,
  "message": "Response submitted for evaluation",
  "response_id": 50,
  "remaining_seconds": 3200
}
同じ質問への二重回答は 409 Conflict エラーで拒否されます。1つの質問に対して1回のみ回答可能です。

5.4 AI自動評価

回答送信後、バックグラウンドジョブ（EvaluateInterviewResponseJob）が自動的にキューイングされ、以下のフローで評価が行われます。

評価フロー

  1. テキスト抽出: 音声/動画の場合、Whisper APIでテキストに変換
  2. MCQ判定: 正解付き選択問題の場合、自動採点（100点 or 0点）
  3. LLM評価: 自由記述の場合、GPT-4oが3軸で評価
    • Relevance（関連性）: 0-100点
    • Correctness（正確性）: 0-100点
    • Clarity（明瞭性）: 0-100点
  4. スコア算出: 加重平均で最終スコアを計算
  5. リジェクト判定: RejectJudgeが即時不合格条件をチェック

評価結果データ構造

{
  "relevance_score": 85,
  "correctness_score": 78,
  "clarity_score": 90,
  "final_score": 83.2,
  "passed": true,
  "reasoning": "実務経験に基づく具体的な回答で説得力がある"
}

5.5 面接の完了

POST /api/interviews/:id/complete

完了処理の内容

  1. 全回答の評価完了を確認
  2. RejectJudgeによる最終合否判定（平均スコア vs 合格基準）
  3. InterviewResult レコードの生成
  4. LLMによるサマリー生成（強み・弱み・採用推奨）

レスポンス

{
  "success": true,
  "message": "Interview completed",
  "result": {
    "interview_id": 1,
    "final_status": "passed",
    "average_score": 83.5,
    "passing_score": 70,
    "total_questions": 5,
    "answered_questions": 5,
    "rejected": false,
    "rejection_reason": null
  }
}

結果レポート（InterviewResult）に含まれる情報

項目説明
summary面接全体の要約（5文以内）
strengths候補者の強み（リスト）
weaknesses候補者の弱み（リスト）
recommendation採用推奨/不推奨
average_score全回答の平均スコア
conversation_log質問と回答の全記録

5.6 セッション管理

タイムアウト

面接セッションは session_timeout_minutes（デフォルト60分）を超えると自動的にタイムアウトします。タイムアウト後の操作は 410 Gone エラーが返されます。

面接の中断と再開

# 中断された面接の再開
POST /api/interviews/:id/resume

# または、トークンによる再開
POST /api/interviews/start_by_token
{
  "access_token": "abc123..."
}

再開条件：

  • allow_resume: true がシナリオに設定されていること
  • 再開回数が max_resume_count 以内であること
  • 面接が abandoned 状態であること

進捗確認

GET /api/interviews/:id/status
{
  "success": true,
  "state": {
    "status": "in_progress",
    "progress": 60.0,
    "answered_questions": 3,
    "total_questions": 5,
    "remaining_seconds": 1800,
    "resumable": true
  }
}

POST/api/interviews/:id/resume面接を再開必要

第7章 管理画面の操作

7.1 管理者ログイン

管理者アカウントは /admins/sign_in からログインします。

Seedデータには管理者アカウントが含まれていません。Railsコンソールから作成してください。
bundle exec rails console
Admin.create!(email: 'admin@example.com', password: 'securepassword')

7.2 面接結果の閲覧（管理者）

/admin/interview_results にアクセスすると、全シナリオの面接結果一覧が表示されます。

一覧画面で確認できる情報

  • 面接ID / 候補者名 / シナリオ名
  • 最終ステータス（passed / failed / incomplete）
  • 平均スコア / 合格基準
  • 回答数 / 質問総数
  • 面接実施日時

詳細画面で確認できる情報

  • 各質問とその回答テキスト
  • 質問ごとの評価スコア（3軸 + 最終）
  • AI生成の評価理由
  • 面接全体のサマリー・強み・弱み・推奨
  • リジェクト情報（該当する場合）

7.3 クライアント管理画面

クライアントは /clients/sign_in でログイン後、自社のシナリオに関する結果のみ閲覧できます。

  • /client/interview_results - 自社シナリオの面接結果一覧
  • /situations - シナリオ管理（CRUD操作）
